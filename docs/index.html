Coding agents don't struggle to write code.

leangraph reads a repository once and builds a graph of what calls what — every function, class, import and reference, each link carrying a confidence score. Describe what's wrong in your own words and it points at the code that has to change.

What it prints

A ranked answer, and why each line is in it.

Why it is quick

Loading is a memory map, not deserialization.

A graph is a file laid out so that querying it needs no parsing step. Opening one is an mmap and a header check, which is why an agent can afford to ask.

How it works

Four passes, and everything after the first is an integer.

01 Discover

The repository's own ignore rules decide what counts as source. Nothing else is read.

02 Extract

One tree-sitter pass per file collects definitions, references — and the comments and docstrings, which are the only part of a repository written in the words its users actually use.

03 Resolve

Three tiers: lexical scope, explicit import, then a name match across the repository. Each edge keeps how it was found, so a proven call never weighs the same as a guess.

04 Persist

Adjacency in both directions, as CSR. callers() is two array reads and a slice — no descent, no decode, no allocation.

Where it loses

The part most tools leave out.

Every number here comes from a script in bench/ that you can run yourself. So do these.

  • It returns nothing useful on a seventh of issues. 14.4% of SWE-bench Verified, and plain keyword search beats it outright on another 5.2%.
  • TypeScript is the weak language. 42.6% against Python's 81.8%. A third of the gap is the benchmark asking a harder question; the rest is a repository that ships its documentation as code, where a demo matches a bug report better than the implementation does.
  • Edge precision is measured on one repository. 78.1% overall and 94.8% at the highest confidence tier, settled by running a real test suite and recording which call actually happened.
  • A one-file change re-resolves the whole repository. Resolution is global: a definition added anywhere can change what a reference elsewhere binds to.
